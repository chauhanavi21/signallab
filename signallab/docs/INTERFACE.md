# SignalLab: interface and motion

The workspace uses a dark blue default theme, a light alternative, a strong typographic hierarchy, and an SVG service overview derived from the current replay. Availability numbers and sparklines come from the analysis response; they are not decorative sample measurements.

## Interactions

- Move through sections with the sticky sidebar or the horizontal navigation on smaller screens. The selected section and thin header progress line follow actual scroll position.
- Press **Ctrl+K** or **Cmd+K** to search workspace sections. Use arrow keys, Enter, and Escape; clicking the search button works too.
- Use the top-right theme control to switch between light and dark. The preference persists locally.
- Use the pause control to stop motion. A system reduced-motion preference also disables the animations; the interface remains fully visible and usable.
- Hover the burn chart to inspect a real request bucket. Focus it with the keyboard and use Left/Right, Shift+Left/Right, Home, or End. Keyboard changes receive a concise screen-reader readout.
- Scroll to reveal panels, inspect chart strokes as they draw, and use the floating back-to-top control after moving down the page.

## Implementation choices

`web/studio.js` provides shared navigation, preference handling, scroll progress, dialog controls, and motion primitives. Each application has its own copy so it remains a standalone project. The three copies are kept in sync. Domain charts and their state remain in `web/app.js`; tokens and responsive layouts live in `web/style.css`.

Motion uses CSS, the Web Animations API, and IntersectionObserver. Scroll and pointer updates are coalesced with requestAnimationFrame; no permanent JavaScript rendering loop runs while the page is idle. Most transitions animate opacity and transforms. SVG line drawing uses stroke dashes for a short entrance animation. Native browser scrolling handles navigation.

Forms retain explicit labels, busy states, and focus outlines. The section dialog is a native modal dialog. Imported names, memo text, and errors are still escaped or assigned as text. No external font, animation CDN, UI framework, or runtime package is required.

## Verification

The browser harness checks the original analysis workflows plus chart inspection, command search, section tracking, back-to-top, light/dark persistence, motion persistence, system reduced motion, card-value fit, and desktop/tablet/mobile layouts. The report is [browser-checks.json](../artifacts/browser-checks.json); screenshots are regenerated by the same command.

The report also records a short local headless requestAnimationFrame timing sample. It describes that browser run, not a guaranteed frame rate on other hardware or a production interaction benchmark. The interface has been exercised in Chromium; cross-browser behavior has not been certified.
